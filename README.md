# 💥 Blast Radius

**See what breaks *before* you ship a schema change.**

Blast Radius is an AI agent that turns [DataHub](https://datahub.com) lineage into
a merge gate. Point it at a proposed column change — drop, rename, or retype — and
it traces every downstream dashboard, ML feature, and pipeline that *actually reads
that column*, names the owners, and drafts the migration. It turns "hope nothing
breaks" into a reviewed, one-glance impact report.

> Built for **[Build with DataHub: The Agent Hackathon](https://datahub.devpost.com/)**.

---

## The problem

Every data engineer knows the fear: you rename or drop a column, hit merge, and
three days later a finance dashboard is blank and an ML model is quietly serving
garbage — and nobody connects it to your change. The lineage exists in DataHub.
Reading it by hand before every change doesn't happen. Blast Radius automates the
judgment.

## What makes it different: **precision**

Naive lineage tools dump *everything* downstream of a table. That's noise. Blast
Radius uses two independent DataHub signals to confirm a real dependency:

1. **Column-level lineage** (fine-grained `upstream_field_refs`)
2. **Real query text** (`get_dataset_queries`)

So when you drop `orders.customer_id`, it flags the customer dashboard and the LTV
feature that read it — and **clears** the revenue dashboard that only reads
`amount`. That distinction is the difference between a useful gate and alert
fatigue.

## Usage

```bash
# Analyze against the bundled sample stack
blastradius analyze raw.orders --column customer_id --fixture examples/sample_stack.json

# Rename instead of drop, and print the migration plan
blastradius analyze raw.orders -c customer_id --change rename --new-name cust_id --migration

# Produce a Markdown report (Mermaid graph + table + migration) for a PR comment
blastradius analyze raw.orders -c customer_id --output markdown

# CI mode: exit non-zero if anything breaks
blastradius analyze raw.orders -c customer_id --fail-on-breaking

# Add a plain-English risk narrative on top of the report (powered by Claude)
blastradius analyze raw.orders -c customer_id --fixture examples/sample_stack.json --explain
```

### AI explanation (optional)

`--explain` adds a short, plain-English narrative of the impact — the kind of
summary you'd paste into a PR description — generated by **Claude** (`claude-opus-4-8`).
It's strictly additive: Claude *narrates* the deterministic report, it never decides
impact, so it can't soften a `BREAKING` verdict. Blast Radius runs fully without it.

```bash
pip install -e ".[explain]"
export ANTHROPIC_API_KEY=sk-ant-...     # or an `ant auth login` profile
blastradius analyze raw.orders -c customer_id --fixture examples/sample_stack.json --explain
```

Without a key (or the extra), `--explain` prints a clean notice and the deterministic
report is unaffected.

## How it uses DataHub

Blast Radius chains the DataHub agent toolkit rather than calling a single endpoint:

| Step | DataHub tool |
|---|---|
| Resolve dataset by name | `search` |
| Walk downstream dependencies | `get_lineage` (direction = downstream) |
| Confirm the column is referenced | `list_schema_fields` + `get_dataset_queries` |
| Attribute owners | `get_entities` |
| Encode the workflow as a reusable recipe | **[DataHub Skill](skills/blast-radius.md)** |

The [`skills/blast-radius.md`](skills/blast-radius.md) recipe is contributed back to
the DataHub open-source project.

## Architecture

```mermaid
flowchart LR
    trigger["Change<br/>(dbt diff / PR / CLI)"] --> agent["Blast Radius<br/>pipeline"]
    agent -->|MCP tools| dh["DataHub<br/>MCP Server"]
    dh --> agent
    agent --> graph["Impact graph"]
    agent --> triage["Owner triage"]
    agent --> pr["Migration draft"]
```

- `lineage.py` — BFS downstream traversal with depth cap + cycle guard
- `impact.py` — column-level scoring (the precision engine)
- `report.py` — Rich console, Mermaid graph, Markdown
- `pr.py` — per-owner migration checklist
- `agent.py` — optional Claude Agent SDK layer to *converse* with the report
- `.github/workflows/blast-radius.yml` — PR merge gate

## Connect a live DataHub

```bash
datahub docker quickstart                 # spin up local DataHub
pip install -e ".[datahub]"
export DATAHUB_GMS_URL=http://localhost:8080
export DATAHUB_GMS_TOKEN=<personal access token>
python examples/seed_lineage.py           # seed the demo stack
blastradius analyze raw.orders -c customer_id
```

With `DATAHUB_GMS_URL` set, Blast Radius automatically uses the live MCP client
instead of the bundled fixture.
